# Invoice PDF Breaker

A Python utility that automatically splits a large PDF containing multiple invoice reports into separate PDF files.

The project uses **PyMuPDF** for PDF processing and **Tesseract OCR** to recognize invoice text from scanned/image-based PDF pages.

---

## Overview

A single PDF may contain many invoices, where:

- Each invoice can contain a different number of pages.
- Invoice pages may be scanned images with no selectable text.
- The first page of an invoice contains invoice-related information such as:
  - `Invoice`
  - `Invoice #`
  - `Invoice No`
  - `Invoice Number`
  - `Invoice Report`
- The company name or other information may appear before the `Invoice` heading.

The script uses OCR to detect the starting page of each invoice and then splits the original PDF accordingly.

---

## How It Works

The processing flow is:

```text
Large PDF
   |
   v
Read each page using PyMuPDF
   |
   v
Run Tesseract OCR
   |
   v
Convert scanned/image text into readable text
   |
   v
Search for invoice-start patterns
   |
   v
Identify invoice starting pages
   |
   v
Split the original PDF
   |
   v
Invoice_001.pdf
Invoice_002.pdf
Invoice_003.pdf
...
```

Tesseract is only used to **recognize text and determine invoice boundaries**.

The final invoice PDFs are created using pages from the original PDF, so the original PDF quality is preserved.

# Tesseract OCR Setup

The input PDF may contain scanned/image-based pages.

In this situation:

```python

```

may return an empty string because the visible text is part of an image rather than an actual PDF text layer.

Tesseract OCR is therefore used to recognize the text.

## Invoice Detection

The script uses OCR to recognize text on each page.

A new invoice can be detected using patterns such as:

```text
Invoice #
Invoice No
Invoice No.
Invoice Number
Invoice:
Invoice Report
Invoice For
```

For example, a scanned invoice may visually contain:

```text
Studio T SQ2 Inc

                     Invoice

                     Date        Invoice #
                     5/31/2020   1598

Bill To
...
```

OCR converts the image into machine-readable text.

The script can then recognize:

```text
Invoice #
```

and identify that page as the beginning of a new invoice.

---

## Example

Suppose `input_pdf.pdf` contains 10 pages:

```text
Page 1  -> Invoice #1001
Page 2  -> continuation
Page 3  -> continuation

Page 4  -> Invoice #1002
Page 5  -> continuation

Page 6  -> Invoice #1003
Page 7  -> continuation
Page 8  -> continuation
Page 9  -> continuation

Page 10 -> Invoice #1004
```

The detected invoice start pages would be:

```text
[1, 4, 6, 10]
```

The program generates:

```text
Invoice_001.pdf -> Pages 1-3
Invoice_002.pdf -> Pages 4-5
Invoice_003.pdf -> Pages 6-9
Invoice_004.pdf -> Page 10
```

## PyMuPDF Returns Empty Text

If:

```python
page.get_text("text")
```

returns:

```text
""
```

but text is clearly visible when viewing the PDF, the page is likely scanned/image-based.

In this project, OCR handles this situation.

---

## OCR Is Slow

OCR is more computationally expensive than normal PDF text extraction.

For a large PDF such as:

```text
74 pages
```

processing may take some time because Tesseract needs to analyze each page.

This is expected.

---

## Output Contains Only One Invoice

If the script generates:

```text
Invoice_001.pdf
```

containing every page, check the console output to see which invoice-start pages OCR detected.

The issue may be caused by:

- Low-quality scanned pages
- Unusual invoice layouts
- OCR reading `Invoice #` incorrectly
- Different invoice-start terminology

Adjust the invoice-start patterns in `pdf_breaker.py` based on the actual OCR output.

## Important Notes

- The original input PDF is not modified.
- OCR is used only for detecting invoice boundaries.
- Output PDFs contain pages copied from the original document.
- Different invoices can contain different numbers of pages.
- The invoice heading does not need to be the first text on the page.
- The script is designed to work with scanned/image-based invoice PDFs.
